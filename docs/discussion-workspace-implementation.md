## 2026-09-05：参考说明交互与引用标题修复

“分支历史”和“原文选区”原来只是不可操作的标签，现在与文档背景一起改为可展开按钮。说明区域采用正常布局，展示完整原文选区或根问题到当前节点的已保存问答；内部列表局部滚动，不覆盖输入框。Escape 先关闭内部详情，再关闭参考说明并把焦点还给触发按钮，审核弹层继续保留。

消息引用标题原来拼接了讨论标题，而讨论标题往往来自创建时选中的长段原文。现在前后端统一使用对应问题的简短摘要和消息角色，最长 48 个字符后加省略号；引用正文单独预览，完整内容仍在展开项中。可核对的旧草稿卡片也使用简短来源名称展示，不迁移已发送快照或修改其正文、版本和定位信息。

浏览器验收覆盖普通讨论和深色审核面板，在 1280px 与 390px 宽度下验证上下文展开、祖先问答查看、完整长选区、引用正文、草稿保留及 Escape 关闭层级。窄屏页面和弹层没有横向溢出。

最终 `make -j 8 check` 通过：430 项测试全部通过，语法、TypeScript、格式检查及生产构建通过。临时浏览器验收页面已清理。

## 2026-09-05：讨论与消息删除修复

删除讨论和消息的前端请求未传 JSON 请求体，公共请求函数因此没有添加 `Content-Type: application/json`，被服务端写请求校验以 415 拒绝。两个删除入口现在显式发送空 JSON 对象，使用现有统一请求头处理，保留服务端校验和原有删除确认。

HTTP 生命周期测试改为直接调用前端 `api.deleteMessage` 与 `api.deleteThread`，测试只补充本地服务地址，不代替前端添加请求头。修复前可复现拒绝，修复后消息和讨论成功删除，引用索引更新，已保存的提案、执行及来源快照继续保留。

`make -j 8 check` 通过：421 项测试全部通过，语法、TypeScript、格式检查及生产构建通过。

## 2026-09-05：精简模型上下文

引用快照仍完整保存在消息和成果记录中，发送前版本校验、来源预览、定位和回写继续使用原有 ID、身份、版本及字符范围。新增 `AgentReferenceContext` 只负责单次请求的模型资料呈现：保留来源名称、路径、正文及简短参考编号，不输出内部追踪字段。

当前引用和补充历史共用一个资料清单，同一来源、范围和正文只发送一次，每条历史问题仍保留对应的参考编号。不同来源、范围或正文不合并，引用编号不跨请求缓存，也不会据此推断原生会话仍记得某份资料。采纳提案的来源回答与参考清单共用同一项，消除重复正文。

普通讨论只展示经过当前正文校验的选区行号，不发送原始锚点对象；同一行存在重复文字时，附上带临时标记的原文，区分具体选中的那一处。失效选区保留引用内容，不编造位置。提案由程序在完整正文中插入临时编辑标记，明确替换或插入位置，原文已有同名标记时自动避让。标记只用于输入，最终应用仍使用已验证的原始字符范围和文档版本。

本次不改变 Codex 开发者指令、原生会话继承、完整文档与增量规则、用户选择的资料范围或提案只读权限。精简只作用于之后发出的请求，已经进入原生会话的历史不会被追溯改写。

验证覆盖模型输入字段、当前与历史引用去重、不同来源与版本正文区分、快照完整保存、原生提案请求，以及编辑和选区标记定位（Unicode、同一行重复文字、重复段落、插入及整篇替换）。交叉检查发现并修复了仅用行号无法区分同一行两个相同选区的问题。

最终 `make -j 8 check` 通过：421 项测试全部通过，无失败或跳过，语法、TypeScript、格式检查和生产构建通过。

输入量示例：使用 4,000 字符来源回答、无附加资料的整篇采纳提案，旧格式共 9,102 字符，新格式共 4,993 字符，减少 4,109 字符（约 45.1%）。这是同一份资料的提示词字符数对比，不是 token 计数，也不代表真实模型回答质量的评测结果。

## 2026-09-05：审查问题修复

本轮修复重点是写入目标、停止与恢复、引用来源和再次执行。问答、提案和执行记录仍分别保存，不改变回答本身的含义。

| 场景 | 修复后的使用方式与行为 |
| --- | --- |
| 关闭准备面板后正文变化 | 整理要求和引用继续保留；旧目标显示“原版本目标，需重新确认”。查看当前原文并确认范围，或重新选择章节／文档末尾后才能生成 |
| 让 AI 继续调整提案 | 提交后立即返回生成状态；停止入口保持可用，结束后保留已有提案、过程和补充要求 |
| 提案或新建文档准备期间停止 | 加载正文、准备快照、原生生成共用停止状态；停止发生在原生提交前时，不再启动回合。新建文档弹窗提供“停止创建”及“后台继续”，关闭弹窗不终止创建 |
| 原生失联或日志暂时不可写 | 普通问答与成果运行均保留待保存的恢复信息；日志保存可重试，迟到的结束事件不会清除它。核对后重置原运行时，恢复后续操作。原文缺失时仍可根据已保存问题生成核对记录 |
| 历史未知结果已经核对 | 保留原有历史标记，后续消息、正文和执行记录照常同步；未知历史不再被当作持续流式输出 |
| 活动 Markdown 已移动或删除 | 仍可核对未知运行、填写执行验证结论、删除已结束的成果记录；这些动作不读取或写入正文 |
| 普通问答的未知结果再次执行 | 显示原问题和原要求，用户明确开始后新建执行记录及子问题；旧问题、部分输出、结果记录保留 |
| 新建文档失败后再次准备 | 恢复原指令、目录及文件名要求，并展示已知的创建路径和原结果；核对后从创建入口明确开始。保留旧记录，并绑定发起时的源文档，避免切换文档后重放旧请求 |
| 查看跨文档引用原位置 | 先只读预览来源和内容；关闭后保留原讨论。用户点击打开来源文档才切换，运行期间仍能预览 |
| 使用新版依据重新讨论 | 输入区包含新版资料、原问题及待评估的旧结论；用户可核对或修改，点击发送后才运行，不改写历史引用 |
| 来源超过单轮引用预算 | 检查继续返回变化状态和新版版本，其余引用不受影响；提示选择更小片段，保留原快照，不静默截断 |
| 路径目标改变后重新关联 | 在资料选择器中显式勾选重新关联当前文件。新来源使用新身份；旧引用显示来源不可用，内容相同也不会自动接到新文件 |
| 24 项资料再次执行 | 对重复来源先去重，再计算数量与字符预算；准备面板显示包含操作来源在内的总量 |
| 删除记录后重放旧请求 | 仅保留请求标识和指纹等去重信息；旧请求被拒绝，不会再次执行。真正的新请求使用新的提交标识 |
| 正文保存后元数据协调失败 | 仅在文件仍是本次写入结果时恢复旧正文；发现其间发生外部编辑或文件删除时保留当前状态并报告冲突 |

架构上，新建文档的文件生成仍由 `DocumentCreationService` 负责，持久化运行、停止和恢复交给 `WorkspaceOutcomes` 统一编排。`OutcomeStore` 保管成果版本和删除后的最小去重信息；`DocumentWorkspace` 继续承担正文与讨论锚点的一致性边界。来源身份由 `ProjectWorkspace` 维护，前后端快照都保留身份与内容版本。

## 2026-09-05：P0-B 至 P2 完整工作流

本次接通提案、执行、比较、工作视图及项目关联。回答保留为问答内容；成果由用户的具体操作产生，保存为独立记录。审核与成果面板采用深色底、细边框和青色重点按钮；比较和讨论延续原有页面风格。

### 操作与结果

| 能力 | 使用方式 | 保存与恢复 |
| --- | --- | --- |
| 采纳到文档 | 从完整回答或片段打开准备面板，选择替换原文、章节或插入位置；确认原文后生成提案 | 使用全新原生只读会话，生成期间不写正文；关闭面板后继续生成 |
| 审核与回写 | 查看来源和完整前后差异；手工调整提案或补充要求让 AI 继续调整；点击采纳后写入 | 保存前后版本和应用记录；重复请求不重复插入，版本冲突阻止覆盖并要求重新选择目标 |
| 撤销采纳 | 已应用记录提供撤销入口 | 正文仍等于应用后版本时安全撤销；有后续编辑时生成反向审核提案，人工调整后再采纳，不覆盖后来内容 |
| 据此执行 | 准备目标、限制、验收条件和资料，检查目录与权限，点击开始 | 指令、来源、执行记录先落盘；沿来源节点分支创建问答；后续执行有新记录，不覆盖旧结果 |
| 停止与核对 | 点击停止，观察停止与收尾状态；必要时进入未知结果核对 | 停止不撤销文件；过程、输出和结果保留。刷新不重发请求。不能确认的运行阻止再次写入，核对原进程和文件后才恢复 |
| 比较与综合 | 开启节点选择，保留全部所选项，以两栏切换查看；确认原始目标、问答及必要祖先片段后生成综合讨论 | 三项以上不丢资料；综合产生独立 Thread 与会话，原节点不改写 |
| 工作视图 | 切换默认、专注、比较、审核、总览；可固定一个参考节点、交换两栏或引用片段 | 保留当前节点、输入、阅读位置与画布变换；固定仅影响显示。窄窗口使用页签和单列审核 |
| 引用到其他讨论 | 选择目标讨论与节点，或新建独立讨论；引用加入输入框后由用户发送 | 被引用数量由已发送消息计算，删除目标消息后不再计数；历史成果继续保存快照 |
| 项目总览 | 左下角项目入口，按最近讨论、提案、执行和已应用成果查看；筛选文档、状态、标题与依据变化 | 汇总登记文档的实际元数据，不从标签推断任务；先只读预览，点击打开文档处理才切换执行对象 |
| 跨文档资料 | 添加引用时选择其他已登记 Markdown；可按路径关联新来源，预览章节和问答 | 不启动其他文档的 Agent；引用固定到发送时版本。文件缺失显示不可用，不猜测同名文件身份 |
| 依据更新 | 对比旧内容与新版，保留当前依据或用新版发起独立讨论 | 只提醒直接引用。原记录不变，保留依据是对当前版本差异的确认，后续变化再次提醒 |
| 来源与成果保留 | 删除来源问答或原文选区后，从文档成果入口查看 | 锚点失效保留 Thread 与问答，重新关联时验证当前正文；显式删除成果仅删除该记录，不回滚 Markdown |

### 架构边界

- `ActivityGate` 负责单活动操作与停止收尾，不把用户请求隐式排队；文档切换和成果操作共用此边界。
- `OutcomeStore` 单独保存成果，负责原子持久化、记录版本与重复请求识别。每篇文档的 `outcomes.json` 与 `threads.json` 同级。
- `ProposalService` 负责提案范围、生成结果解析、编辑、正文版本比较、应用及反向审核。正文写入仍通过 `DocumentWorkspace`，不绕开锚点协调。
- `WorkspaceOutcomes` 编排准备、先存后执行、过程留档、停止与恢复；`ConversationService` 保留问题和分支一致性职责。
- `CodexAppServerRuntime` 负责原生只读策略、主回合与子回合中断、权限请求处理、真实终态和进程信息。UI 关闭不充当停止。
- `ProjectWorkspace` 管理文档索引、只读来源解析与版本检查。资料版本比较与画布布局没有依赖。
- `OutcomeWorkspace` 组合前端操作；准备、审核和项目列表各自是独立组件。`DiscussionWorkspaceContext` 提供动作契约，讨论树无需知道 HTTP 或提案存储细节。
- `discussion-view-state.ts` 保存视图状态并组装比较来源；引用快照由服务端重新验证。画布坐标、固定状态、未提交选择不会写入提示词。

默认数据目录仍为 `~/xuanniao`；可通过 `XUANNIAO_DATA_DIR` 指定其他本地目录。项目索引也保存在此目录中，项目外文档单独标记。既有项目内讨论元数据在打开项目总览时登记迁移。

当前项目边界和 Agent 执行目录沿用服务启动目录。目录树浏览、只读预览及打开项目外文档不会隐式更换项目或执行目录；执行准备面板始终显示实际目录。

### 验收口径与边界

提案只覆盖当前 Markdown；直接执行可按当前原生权限修改仓库文件。执行结束与验收结论分开，默认标记未核对，用户记录通过或失败时必须填写证据。服务崩溃前未落盘的输出不承诺恢复，不以缺失日志推断动作未执行。版本检查在打开或手动刷新时进行，不依赖文件监听，也不自动传播结论有效性。

本地 HTTP 与浏览器验收使用临时 Markdown 和 Agent 测试桩，覆盖实际请求、持久化和界面状态，不等于真实模型回答质量评估。原生只读策略另有本机沙箱拒绝写入验证。

## 2026-09-05：P0-A 首个可用增量（历史记录）

本轮交付上下文选择、引用保存和独立讨论的主流程。界面沿用现有文档／问答／讨论树三栏，使用浅蓝背景、细边框与青色状态提示；问答内容仍占主要区域，参考信息默认收为摘要和可展开卡片。

### 已实现的功能与使用方式

1. **本轮参考**：文档选区提问与讨论输入区展示文档背景、选区及是否继承分支历史。点击说明可以查看范围含义；“仅所选资料”不等于限制文件访问权限。
2. **同文档引用**：点击“添加引用”，搜索全文、章节、问题或回答；预览 Markdown 原文后引用整项或选中片段。章节包含其子章节。引用卡片展示范围、版本和内容，支持移除。
3. **快捷引用**：稳定消息旁提供“引用”，消息选区浮层提供“引用到输入框”；消息选区也可拖入参考栏或详情中的后续问题输入框。选区无法唯一映射到原文时明确提示通过资料选择器重新选择，不猜测范围。
4. **引用版本与历史**：发送前核对服务端来源版本；失败时保留草稿并显示错误。未发送卡片可对照当前内容并更新；无法确定新范围时要求重新选取。消息保存实际使用的内容快照，刷新后可回看、定位来源；原讨论删除后仍保留快照并标明原位置不可用。
5. **独立讨论**：详情顶部打开准备面板，默认列出当前节点的问题与回答；核对或调整资料，选择文档背景范围，填写新的问题，再点击开始。新讨论有独立 Thread 和原生会话，可回到来源讨论。同一原文选区的独立讨论不会被普通选区提问误复用。
6. **会话重建提示**：无法沿用原生会话时，在执行事件和回答中说明正在依据问答重建，部分工具状态可能缺失；重建提示词要求在继续修改前核对当前文件与必要的执行事实。

本轮同时提前加入两项基础调整：执行中的活动文档切换保护；将节点类型收为可选历史标签，移除任务、风险、决策数量统计。原数据保留，标签不改变 Agent 权限或运行方式。
